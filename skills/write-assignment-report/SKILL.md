# 과제 보고서

교수님이 제공한 문제지와 제출 양식을 먼저 확인한다. 별도 양식이 없으면 기존 보고서처럼 `1) 소스` → `2) 설명` → `3) 결과` 순서로 구성한다.

## 1) 소스

- 보고서 전체를 준비할 때 이 항목에 전체 소스를 붙일 자리를 남긴다. 전체 코드는 사용자가 직접 붙인다.

## 2) 설명

### 설명 범위와 순서

- 과제의 목적과 사용자가 지정한 함수·범위를 먼저 확인하고, 해당 범위의 의미 있는 코드를 중심으로 설명한다. 소스 전체를 기계적으로 설명하지 않는다. 예를 들어 `main` 함수 내부만 요청하면 그 범위에서 작성한다.
- 분석 대상이 여러 파일이면 파일별로 구분하고 동일한 상세도를 유지한다. 특정 파일부터 요청하면 요청한 파일부터 작성한다.
- 기존 코드와 개선 코드가 함께 있으면 기존 코드부터 설명한다. 개선 코드는 기존 설명을 반복하지 않고 추가·변경·삭제된 부분과 변경 이유를 중심으로 설명한다. 삭제된 부분은 기존 코드 조각을 인용하고 삭제 이유를 설명한다.

### 코드 조각과 상세 설명

- 선택한 범위 안에서 소스 순서대로 설명할 코드 한두 줄이나 함수 일부를 코드 블록으로 먼저 제시하고, 바로 아래에 해당 내용을 문단으로 서술한다. 함수가 길면 관련 줄을 나누어 설명한다. 입력 데이터와 라벨 설정처럼 함께 이해해야 하는 줄은 한 블록에 묶는다.
- 자료형, 변수, 배열, 포인터, 구조체는 설명 대상에 처음 등장할 때 각각의 의미와 실제 코드에서의 역할을 설명한다. 선언문도 포함하며 변수에 어떤 값이 저장되는지, 배열에 무엇을 담는지, 포인터가 무엇을 가리키는지, 구조체와 멤버가 무엇을 나타내는지 짚는다.
- 함수는 전달 인자, 반환값, 실행 목적, 실제 코드에서의 역할을 구분해 설명한다. 전달되는 값과 그 의미, 반환되는 값이 사용되는 곳, 함수가 수행하는 작업과 과제의 처리 흐름에서 쓰이는 이유를 해당 코드에 연결한다.
- 중요한 조건문은 조건이 성립하는 경우와 성립하지 않는 경우의 동작을 설명한다. 반복문은 반복 조건이 성립할 때 수행하는 작업과 조건이 성립하지 않아 종료되는 경우를 설명한다. 해당 코드에 조기 종료 조건이 있으면 함께 설명한다.
- 반복문, 분기, 공식은 문제에 나온 값을 넣어 어떤 값이 계산되거나 갱신되는지 보여 주고, 계산 결과가 어디에 쓰이는지 설명한다.
- 과제에서 요구하는 표나 수식은 관련 설명 바로 뒤에 넣는다. 계산형 과제는 사용한 기준이나 식을 밝히고 대표 사례의 계산 과정을 보여 준 뒤, 요구하는 전체 값을 표나 수식으로 정리한다.
- 코드, 설명, 표, 수식의 변수명과 수치가 일치하는지 확인한다.

## 3) 결과

- 실행 캡처는 사용자가 직접 붙인다. 보고서 전체를 준비할 때 캡처를 붙일 자리를 남긴다. 최종 답을 표나 수식으로 제출하는 과제는 계산 결과를 정리한다.

## 마무리

- 과제에서 요구한 설명과 결과로 끝낸다. 느낀 점, 깨달은 점, 배운 점, 소감, 회고를 임의로 쓰거나 별도 결론으로 덧붙이지 않는다.
