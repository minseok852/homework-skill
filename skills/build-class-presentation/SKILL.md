# 수업 발표 PPT

## 그림 자료 먼저 확인하기

- 슬라이드 구성에 앞서 첨부 자료에서 활용할 사진, 실행 화면, 간단한 그림을 확인한다. 그림 자료가 보이지 않고 사용자가 보유 여부를 밝히지 않았다면 사용할 이미지나 캡처가 있는지 먼저 한 번 묻는다.
- 이미지는 첨부하고, 이미지가 없거나 첨부하기 어렵다면 발표에 넣을 내용이나 원하는 그림의 설명을 글로 붙여넣어도 된다고 같은 질문에서 안내한다.
- 사용자가 이미지가 없다고 하면 제공된 글을 바탕으로 편집 가능한 도형과 짧은 라벨로 핵심을 보여준다. 순서나 연결 관계를 이해하는 데 도움이 될 때 화살표를 추가한다.

## 발표 흐름 잡기

- 교수님 공지, 채점표, 제공된 템플릿, 발표 시간을 확인한다. 슬라이드 구성부터 논의해 달라는 요청이면 제목과 각 장에 넣을 그림을 먼저 제시한다.
- 실제 문제 사례나 확인한 결과를 앞에 배치한다. 프로젝트 발표는 문제 상황 → 해결 방안 → 확인한 결과가 이어지도록 구성하고, 기술은 해결 방안에 어떤 역할을 했는지 설명한다.
- 한 장에 메시지 하나를 담는다. 제목을 핵심 메시지가 드러나는 명사구로 쓰고, 제목만 순서대로 읽어도 발표 흐름이 이어지는지 확인한다.
- 코드 캡처와 줄별 코드 설명은 생략한다. 문제 상황에서 어떤 방안을 적용했고 무엇이 달라졌는지 보여준다.

## 그림 중심으로 슬라이드 만들기

- 그림을 슬라이드의 중심에 크게 배치한다. 화면 캡처, 비교 이미지, 도식 등 핵심 메시지를 가장 잘 보여주는 자료를 고른다. 각 그림에 무엇을 보여주는지 한 줄로 설명한다.
- 동작 방식이나 처리 흐름을 쉽게 설명할 수 있을 때 도형과 화살표를 사용한다. 짧은 라벨과 실제 연결 방향으로 흐름을 보여준다.
- 제목, 본문, 그림 설명, 도식 라벨은 발표 화면 뒤쪽에서도 읽을 수 있도록 크게 쓴다. 글자 굵기와 여백으로 제목과 본문의 위계를 보여준다.
- 본문은 짧은 명사구로 쓴다. 설명할 항목이 여러 개면 명사구를 불릿으로 정리하고 항목 사이에 여백을 둔다.
- 내용이 넘치면 중복 문구를 줄이고, 필요한 내용이 여전히 많으면 슬라이드를 나눈다. 그림과 글자의 크기를 유지한다.

## 발표본 검토

- 그림이 장의 중심인지, 한 줄 설명만으로 핵심이 드러나는지, 본문과 그림 안의 글자까지 읽히는지를 우선 확인한다.
- 그림과 수치를 제공 자료와 대조한다. 발표 시간 제한이 있으면 시연이나 질의응답 시간도 조건에 맞춰 반영한다.
- PPTX를 요청받으면 편집 가능한 파일로 제작하고, 렌더링해 글자 크기, 줄바꿈, 겹침, 그림의 가독성을 점검한다.
